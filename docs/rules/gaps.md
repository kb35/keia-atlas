# Known gaps

Where the code does not yet follow the book. Small, safe fixes were made when the book was written (29 Sept 2026); these are bigger. Fix one, then delete its line.

1. **Typed-in durations in page scripts (M1).** Learn has about 30 `.animate()` calls with their own numbers (200 to 900 ms) and curves; Spaces and Scenarios have a few each. Move them to `rsMotion()`, keeping the feel.
3. **Older tokens (M1).** `--dur-fast`, `--dur` and `--dur-slow` in `base.css` predate the motion tokens.
4. **The fault outline is written twice (D6).** `.rs-radiate` in `motion.css` is the shared version (a still fault outline since v2; the pulse is retired); Spaces still defines its own. Move it onto it.
5. **Several "Simulated" labels (P5, W8).** `SimTag` is the one tag now, with two wordings, "Simulated" and "Simulated live". Pages not yet converted still use `.tag.sim` and `.sim-tag` with wordings such as "Demo figures".
6. **Find and filter (P1).** Every list page uses `FilterBar`, the Schedule included. Search and Learn keep their own find boxes on purpose.
7. **Undo is not everywhere (P7).** Report, project tasks (status and owner) and a project's change requests have it; approving a knowledge change on the Proposals page does not.
8. **Glossary words are explained only in Learn (W2).** First-use tooltips on every page are not built.
9. **Checked by eye (D3, M5, W4, T3).** No automatic check yet for drawing part names, the 8 view transition names per page, or em dashes. `tools/contrast-check.mjs` checks the health palette in every look; the other text colours are still checked by eye.
10. **Paths are hidden on phones (L6).** The top bar drops the path under 768 px; deep pages only link one level up in their first line there.
11. **Live only between windows on one computer (P7, decision 0025).** The live layer's transport is the browser's BroadcastChannel. A sync server replaces it by providing the same `send` and `listen`; until then pages say "Live between windows on this computer (demo)". Project tasks (status, owner), a project's change requests, the task page's owner and the Schedule's assigning use it so far.
12. **Pages not yet on the shared parts (L1, L9).** Every page is converted except Learn, Search and About.
13. **Learn's motion checks (M7).** Learn's 30 `animate()` calls check reduced motion only three times.
14. **Schedule time off is not approved by anyone (P7).** A request from the Month view is kept in this browser (`rs4-pto`) and shows as pending; no manager approves it, and it is not a live-layer event. The Year view's team load is worked out when the site is built, so it does not follow assignments made on the page.
15. **The Spaces and Devices overviews are a simulation (P5).** `/locations/` (was `/rooms/overview/`), the office, region and home-office pages under `/locations/`, and `/devices/overview/` run `src/lib/livesim.mjs` on the usage and health data, labelled Simulated. When real feeds replace it (the same shape: monitoring, room booking, occupancy sensors, device management) replace `snapshot()` with the same shape; the pages do not change. Which units run firmware behind the standard is made up too; only the Poly line has release data, so other models name no versions.
16. **Every width, the other places (L10).** The frame, the shared parts and the Work pages follow L10. Spaces, Devices, Team and Learn pages still use `@media` breakpoints (760, 900, 1100 px) and a few sideways scrollers; Vendors' table runs past the window at 1024 px. `tools/responsive-check.mjs --all` lists them. The live overviews still clip sideways (`LiveSide.astro`, `overflow-x: clip`), a workaround the filter bar no longer needs, and could say "Simulated live" (`PageBand sim="live"`).
17. **Comms rooms and racks (decision 0028).** Access points are units in each office floor's "Open areas and corridors" space (placed on the floor plans), but the sizing method counts no access points, and no space type has one, so the 23 meeting rooms of 12 or more seats that the Wi-Fi standard wants one in are gaps (listed in each floor file's notes). The UniFi pilot's outgoing Cisco units count as units of the new model on its model page, because a unit has no model of its own. The switch class is named "In-room network switch" and the gateway class "Home network gateway", though comms rooms use both. The UniFi models' profile pages show the class outline: their traced fronts are in the rack view only. The Cisco, Palo Alto, ZPE, APC and ADVA fronts follow their rack-gear descriptions, not a traced drawing. Sizing (`sizeFor` in `src/lib/comms.mjs`): the UPS is not sized (no load or runtime recorded), PoE draw is only known for models that state it, the panel size and rack sizes are house figures, and no project is built from the Network refresh playbook yet, so every older comms room says "due in the network refresh, 2027". The `data/rack-layouts/` typical layouts are no longer shown anywhere (there is no standard rack) but stay for the cross-reference checks.
18. **Deploy's checks are a simulation (P5).** `/projects/<id>/integrate/` and its batch and space pages ask the plan in `src/lib/integrate.mjs` what the systems hold; real asset register, DNS, device management and switch-port feeds answer instead, with the same shape. Recheck, Update and Apply are answered by `src/lib/integrate-client.mjs` after a pause, in the window that asked. Accepts sit on the batch, space or project item, so a unit's own History shows its checks but not the accept (the batch's History does). Which units a refresh changes is read from new units on their way and the project's name; a project should say it. Each unit's build sheet (`/projects/<id>/integrate/<batch>/<unit>/`, `src/lib/buildsheet.mjs`) works its values out from the data and `data/house-values/`; the IP address and switch port are the simulated plan's, and what the data does not hold is shown as Not recorded: MAC addresses, the ChromeOS compute system a MeetUp 2 pairs with, office opening hours, the VLAN for AV switchers and amplifiers (the network standard's plan does not name them), firmware targets for models without a firmware line, and values measured on site.
19. **A project's baseline is partly derived.** The timeline's planned bars use each recorded phase's `planned` date; phases not reached yet share the time to the target by the playbook's weeks. A `baseline` per phase in the data would make it a real baseline. The log (risks, issues, decisions, dependencies) is read from the data with no form to add an entry, and dragging a card between columns needs a pointer (the status menu does the same on touch).
20. **Port positions not in the model data (R7).** Cables in space drawings start at the model's `face` and `order`; these models lack them for ports the wiring uses, so a house default stands in (rear face, lower third, spread about the middle): Netgear M4250-9G1F-PoE+, Logitech MeetUp 2, Cisco Desk Pro, Poly PoE injector, Kramer TP-580RXR, BrightSign XT1145, StarTech US1GC30B, UniFi Express 7, both Canon printers, Kramer Galil 6-C, Poly Studio Expansion Microphone, Poly IP Ceiling and Table Microphones (face and order); INOGENI U-CAM, Logitech Scribe, Logitech Tap Scheduler (face); Poly Studio E60, Apple Studio Display 2026 (order). Profiles name no display model, so screens use the default too. The busiest tracks (two screens, a switch and a switcher) still show some crossings where cables drop out of the bundle to their ports.
21. **Spaces and floors (R8, decision 0030).** Every office has floor files and a 3D model (`/locations/<site>/3d/`), all one made-up building type sized to the busiest floor (`tools/migrations/2026-09-30-office-floors.mjs`). Where a comms room's recorded patching has fewer live ports than the floor has outlets, the outlets with nothing plugged in are spare (terminated, not patched): 65 across the nine new offices. Only New York and Dublin record two providers. The 3D view frames the whole building from the ground, so the top floors of a tall one (New York at level 20, Tokyo at 15) look small until you pick a floor. The space drawing ignores a space's variations (size, mirror, door, columns). The 3D page has no place tab until the sidebar's Locations reorganisation (Shell's NAV is shared). Office space counts include each floor's open areas and corridors space.
22. **Drill-downs not yet done (P10).** `tools/drilldown-audit.mjs` still lists: the Schedule's "Over-booked" opens `?zoom=`, which is not a filter (ScheduleViews). Back after a drill-down lands higher than you left on Home and the Spaces overview, as it did before P10: the router restores the scroll before those pages reach their full height (Home's role panels show once `data-role` is set again; the live tiles paint later). The Spaces and Devices overviews' office counts are live, so a count can move by one between the click and the list. Space usage's "In use now" is worked out on the page, so it follows the page's own settings, not the address alone; Planning's figures follow the scenarios adopted in this browser's live layer, so a drill-down from an adopted scenario's figure lands on the Work plan's baseline count.
23. **Known errors (decision 0029).** `/known-issues/`, its known error pages and manufacturer cases have no place tab: Shell's NAV is shared, and the tab (Work, after Incidents) is still to add (`tab:known-issues` already has a help card). Unit firmware versions are simulated (the Devices overview's rule), and Logitech, UniFi and Netgear versions aren't tracked, so their units count as "may affect us". The Logitech, UniFi and Netgear feeds are made up. Tell the team records a note per space (`room-note:<space>` in the live layer); space pages show it ("Notes from the team", from the live layer in the browser). "Propose a firmware rollout" records the proposal; it doesn't create a project (there is no new project page). A Poly issue that Poly lists only as fixed doesn't say which versions it affected; Aigna's reading is in `affected_note`.
25. **Planning is a model, not a record (P5).** Every price, hour and ratio in `data/planning/` is a house assumption (the benchmarks that exist cover endpoints or the service desk, or are paywalled). Which units a live project replaces is inferred (its spaces, and units due by the year it ends), because a project does not list them; a cut defers a share of every office's replacements, not named spaces (the usage score could pick them); a scenario that moves work between years moves spaces in proportion; a typed scenario lives in this browser's live layer only, like every other live change. The Planning page uses `section="budget"` until the Work tabs are reorganised (one Planning tab, Work plan kept).
26. **Locations and Services (P5, `src/lib/services*.mjs`).** Office pages (`/locations/<site>/`) read the three service lights from Services (`serviceHealth(site)` in `src/lib/services-view.mjs`: the same simulation and rule as the service pages), and each light opens that service for the office. Every office has a floor map, internet circuits and a 3D model. "On site today" is the demo's today (28 Sept) from people's office days; people have no page of their own yet, so they open `/team/?p=`; the "On site today" figure opens the Team page filtered by Office today. Vendors have no page of their own, so they open `/vendors/` filtered. `/services/` and the three service pages run `livesim.mjs` on the kit each service owns, labelled Simulated live. Network shows the access points (units in each floor's open areas), the Wi-Fi controllers (4) and the 100 home gateways; home gateways, circuits, UPS, power strips, out-of-band consoles and links get made-up health (`SIM_KIND`), higher than real kit so a demo shows a fault now and then. Circuits are read from the racks' provider boxes (Dublin and New York have two); other offices' circuit details are not recorded. Printers belong to no service. Firmware versions are named only for the Poly line; rack equipment has no firmware data. "Comms rooms to standard" needs switches on the house standard (UniFi), so only the pilot spaces pass. There are no meetings or signage sub-views of AV (the Kind filter does it). The search entries (`searchItems()` in `services.mjs`, kind `svc`) are not merged into the search index until `search-query.mjs` has a Services group.
31. **The room guide (`/guide/<room>/`, `src/lib/guide.mjs`).** Guides exist for meeting rooms, huddle rooms, focus rooms and offices; shared spaces, desks and home office kits have none yet. Reports and requests go through the live layer, so they reach other windows on this computer only, and nothing files a ServiceNow ticket. A reported incident has no page of its own: its card on the Incidents board, office page and Home opens the space page, and it stays New (no one can take or resolve it). Requests show only on the space page until the service desk queue exists. How a call starts assumes every room system is a Google Meet room that joins Teams and Zoom as a guest; the spaces' platform is not in the data. Lights and blinds are not in the data, so the guide says nothing about them. The employee layout (`src/layouts/Guide.astro`) has no help mode. The QR code points at the public site, not the dev server.
32. **Old words still around.** The text in `data/` now says space type, manufacturer and known error (30 Sept clean-up). What is left: the field names `maker`, `layer: profile` and `layer: room-type` in the data and its schemas (they are keys, not words on screen); generic "room" in device type, setup guide and standards text where it means a meeting room or reads naturally ("the room's verification" became "the space's verification"); "site" for an office in some playbook steps; the old-word synonyms kept on purpose for search; the one-off migration scripts in `tools/migrations/` and the decision records, which are history; and text in `src/` (the Changes example, the unit page's "Known issues for this firmware", code comments). The addresses `/rooms/`, `/room-profiles/`, `/configurations/`, `/known-issues/` and `/changes/` keep their names until a Moved page is added for each.
33. **The front door and the method pages (`/welcome/`, `/method/`).** The front door lives at `/welcome/`, not the root: Home keeps `/`, which the sidebar, the mark, lessons and help cards link to. The hero is a fixed simulated moment (3.09 Whooper Swan's video bar offline since 07:52, with Liam), drawn from the real Dublin third-floor plan by its own `HeroPlan`, not the `livesim` feed, so the demo's own pages may not show that fault. The front door's device list, key and morning strip use the shared `HealthGlyph` (lit at once: the front door has no Shell to light it). The rings drawn inside the hero plan's own SVG still come from `src/lib/ring.mjs` (`ringParts`), because they sit at plan coordinates in metres; they match the HealthGlyph shapes, and colours use the v2 tokens (`--h-fault`, `--quiet`) with the v1 colours as fallbacks. The method pages have no sidebar entry or place tab (Shell's NAV is shared), use `section="method"`, and read every word of method text from `docs/keia-method.md` at build (`src/lib/method.mjs`; `tests/method.test.mjs` fails if its shape changes). Not built yet: the "For leadership" page with the cost model, the partners page, Learn lessons and help cards re-pointed to the five ideas, and a Settings switch for modules (the modules page's Try it says so). The front door shows the Studio look only.
34. **Health glyphs and the band, v2 round V1 (UI-V2 §6, §8).** Every status dot is a health glyph except the check lights on HealthCard and the unit page (`.hr-c`, `.dv-c`: a filled circle with a tick or cross while a check runs). Place and event markers (`day-dot`, the feed's `lv-ek` bars) and the phase rail are not health and stay. Settings has no switch for the demo feed yet (it is shared; `?feed=off` does it). Some live pages write their answer sentence when the site is built rather than from the feed: the Deploy pages, the 3D office, home offices and Planning's year. The room guide's report, request and table card pages have no answer line (V8 rebuilds them), nor do the method pages (`MethodPage.astro`: reference pages, their lede says what they hold). The Drawing set's hatched Fault background (`.hg-soft-fault`) is defined but no plan uses it yet.
35. **Navigation, v2 round V2 (UX-V2 §2).** Modules are demo settings in this browser (`rs6-modules`); Connected changes only the sidebar's source mark, not where the records come from. Routes keep their addresses: only the two renamed places moved (`/work/` to `/support/`, `/devices/overview/` to `/assets/`); spaces stay at `/rooms/` and units at `/device/?tag=`, not `/spaces/` and `/assets/<unit>/`. Pages still pass `minStage` and a few elements still carry `data-min-stage`; both are ignored. A few pages' own links still name `/work/` (the router goes straight to `/support/`). The zoom pairs a shape with the next page's picture from region to office and from office to space and back (a room on the plan, by a stand-in box); into a unit it is the page move only, because the unit page draws itself once its data is in. Escape on the plan (clear, then zoom out) waits for the plan's selection (round V6). Phones show no path, so zooming out there is Back. The palette's Do mode lists the Shell's buttons, the band's action and the path's parent step; Take, Hand to, Park, Run rule and Set depth join when their buttons exist (V3, V5). Ask offers the glossary and the method's idea pages, not the Level 2 and 3 pages. The "Modules and agents" lesson still teaches the old ladder (six steps on a slider): it needs rewriting with the Learn lessons (V4 H3).
